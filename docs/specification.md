# Внутреннее техническое задание

## Проблема и пользователи

NEXUS помогает продуктовому аналитику, руководителю продукта и команде разработки быстро понять привлечение, активацию, вовлечённость, удержание, монетизацию, использование функций и результаты экспериментов. Portfolio-цель — показать полный, проверяемый цикл аналитической разработки без персональных данных и обязательных расходов.

## Функциональные требования

Система генерирует версионированные синтетические таблицы, останавливает конвейер при критической ошибке, рассчитывает документированные метрики, публикует агрегированные JSON-витрины и показывает 11 русскоязычных разделов. Интерфейс не рассчитывает бизнес-метрики, а только форматирует безопасные результаты конвейера.

## Нефункциональные требования

Результаты воспроизводимы при одинаковых seed и версиях; код типизирован, модулен и не зависит от глобального состояния. Интерфейс адаптивен, доступен с клавиатуры, не требует JavaScript-библиотек и не отправляет данные третьим сторонам.

## Критические решения

- Python без обязательных runtime-зависимостей для переносимого конвейера.
- CSV как прозрачный слой источника; агрегированные JSON как контракт интерфейса.
- Статическое размещение вместо постоянно работающего backend: нулевая поверхность операций записи, нет холодного старта и обязательной базы.
- Двусторонний z-тест независимых долей для большой бинарной выборки; для множественных сравнений — Benjamini–Hochberg.

## Правила данных

Активность — создание проекта, создание задачи или содержательное действие. Активация — создание проекта, затем задачи не позже 7 календарных дней после регистрации; повторения не увеличивают счётчик. Неизвестные события, нарушенные внешние ключи, дубликаты ключей, неверные даты и суммы останавливают конвейер.

## Граничные случаи

Нулевой знаменатель, нулевой отток, отсутствие подходящей когорты и пустой период дают `NULL`, если значение не определено. Пустая таблица пользователей — предупреждение при наличии корректной схемы; отсутствующая таблица — критическая ошибка. Некорректные сегменты и неизвестные события отклоняются белым списком.

## Приёмочные критерии

- Все критические проверки, lint и тесты проходят.
- Набор с одним seed генерируется побайтово одинаково.
- Каждая метрика имеет формулу, источник, версию и golden-тест для критической логики.
- Нет секретов, PII, wildcard CORS, встроенных скриптов и пользовательского SQL.
- Все пользовательские строки и документация на русском, кроме технических идентификаторов.
- Статический production отвечает, маршруты и JSON-витрины доступны, заголовки безопасности применены.

## Готовность

Definition of Done: реализация, тесты, качество данных, CI, документация, аудит безопасности и русификации завершены; production развёрнут и проверен. До фактической проверки production статус не может быть `READY`.
