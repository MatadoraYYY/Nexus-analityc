# Политика безопасности

## Поддерживаемая версия

Исправления безопасности выпускаются для текущей основной версии.

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в открытой задаче. Используйте раздел GitHub **Security → Advisories → New draft security advisory** этого репозитория. Укажите затронутую версию, шаги воспроизведения и возможное влияние; не прикладывайте реальные секреты и персональные данные.

## Модель угроз

Публичная версия — статическое приложение только для чтения. Она не принимает SQL, не выполняет пользовательский код, не хранит сессии и публикует только агрегированные синтетические данные. Остаточные риски: уязвимость цепочки поставок, ошибочная публикация секрета, XSS при будущем добавлении пользовательских данных и неправильные заголовки hosting.

## Меры

- CSP, запрет встраивания, `nosniff`, ограничение возможностей браузера.
- Экранирование строк перед вставкой динамических данных.
- Минимальные разрешения GitHub Actions: `contents: read` по умолчанию.
- Проверка секретов Gitleaks и аудит зависимостей через `pip-audit`.
- `.env` исключён из Git; `.env.example` не содержит значений.
- В логах и наборе данных запрещены секреты, токены, адреса, телефоны, реальные email и IP.

## CORS и SQL

Статический API обслуживается с того же origin и не выдаёт wildcard CORS. Эталонный SQL использует привязанный параметр `:report_date`; конкатенация пользовательского ввода запрещена.
